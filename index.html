Hello from my CI/CD pipeline! Version 3

Suggested learning order Create the EC2 manually in the AWS console, so you understand what Terraform automates. Do Phase 1 (Terraform only). Do Phase 2 (Ansible only). Push to Git (Phase 3). Use the shell script (Phase 4A). Move to GitHub Actions (Phase 4B).

Learning roadmap

Each stage works on its own, so you always have something running.
Stage 1: Launch the Jenkins EC2 and install Jenkins, Git, Terraform and Ansible.
Stage 2: Create the GitHub repo with index.html. Create a Jenkins job that pulls it (manual “Build Now”).
Stage 3: Add Terraform to the job so it creates the web EC2.
Stage 4: Add Ansible so it installs nginx and deploys index.html.
Stage 5: Turn it into a Jenkinsfile (pipeline as code) with stages: Checkout → Terraform → Ansible.
Stage 6: Add a GitHub webhook so a git push triggers it automatically.
Stage 7: Add Prometheus and Node Exporter for monitoring.
 Things to know up front
Credentials: Jenkins needs your AWS keys and the SSH private key. These go in Jenkins → Manage Credentials, never in Git. (Better still, attach an IAM role to the Jenkins EC2 so no keys are needed.)
Webhook: GitHub must be able to reach Jenkins (port 8080 open to the internet). To begin with you can skip it and use “Poll SCM” or manual builds.
Re-running: The second push will run terraform apply again. Terraform sees the EC2 already exists and changes nothing, and Ansible just updates index.html. This is called idempotency and it’s a key DevOps concept.
Cost: Run terraform destroy when you finish a practice session.
